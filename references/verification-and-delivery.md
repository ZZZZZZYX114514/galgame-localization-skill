# 运行验证、备份与迁移

## 闪退定位

保留可复现的原版与当前失败构建，记录工作目录、启动方式、发生时间、退出码和异常模块。每次只改变一个可定位的因素，并记录结果。

| 测试 | 用于缩小的范围 |
| --- | --- |
| 原版文件与原启动方式 | 基础运行环境 |
| 原内容重打包 | 索引、结束标记、压缩和文件顺序 |
| 只替换一个最小文本条目 | 记录长度、控制码和编码 |
| 只替换一张已确认的按钮资源 | 位深、尺寸、蒙版与状态布局 |
| 加入字体或解码调用补丁 | 字符集、代码页和路径读取 |

NEKOPACK4A 原内容重打包失败时检查零文件名长度结束标记、索引长度是否包含标记、数据起点、文件名原字节及可选资源查找。解析器回读通过的包仍需实际启动。

中文乱码或空字先沿文本到宽字符再到字体渲染的调用链检查。路径或资源缺失检查当前目录、文件名编码和解码补丁的作用范围。

用户限制图片访问时，可检查进程存活、响应状态、异常日志、文件访问和已定位的数值状态。运行时间与存活状态只能支持相应的启动结论，页面布局和剧情分支按实际执行程度记录。

## 稳定版备份

用户确认某一阶段可用后，将该阶段的全部修改文件、启动脚本及安装要求保存到独立目录。清单记录每个文件的相对目标路径、原版及当前 SHA-256、版本和修改范围。

恢复时先退出游戏，检查备份哈希，再恢复这一阶段匹配的全部文件。构建先输出到暂存目录，验证后再安装到运行目录。开始覆盖前检查目标版本与所有输入文件，保存可恢复的目标快照。

多文件安装期间发生错误时，记录已替换清单并恢复快照，然后验证恢复结果。重新应用前重新检查目标状态，识别原版、同一补丁版本和中断产生的混合状态。

## 汉化补丁迁移

先列出当前版本实际修改的文件，保持其相对于游戏根目录的结构，并加入必要启动脚本、安装说明和哈希清单。接收设备需要准备兼容版本的原版游戏。

安装说明写明游戏根目录的识别方法、覆盖目标、工作目录、所需字体或运行库和恢复步骤。目标设备仅需运行时所需文件。构建用 Python、提取表和翻译缓存按用户实际需求提供。

用干净副本验证补丁覆盖结果，逐项比较目标文件哈希。完成后确认原有未修改文件可继续使用。其他设备的显示、字体与运行效果仍需要在实际设备验证。

## 存档与鉴赏记录

用户要求迁移进度或鉴赏解锁时，定位游戏真正写入的目录，可结合文件时间与进程文件访问。Windows 游戏可能使用安装目录、`%APPDATA%`、`%LOCALAPPDATA%` 或注册表。非 Unicode 程序的系统语言会影响文件夹名。

退出游戏后独立备份存档并记录哈希。鉴赏开关、已读记录、剧情变量、设置和普通存档槽可能处于不同文件，也可能共用一个容器。迁移说明写明要复制的文件及覆盖影响，并要求目标设备先备份现有记录。

用户明确要求修改鉴赏解锁时，先依据当前版本的读写逻辑确认字段结构、数量、偏移与有效值。解析可变长字符串后再定位后续字段，验证所有非目标字节。写入后解码回读，条件允许时确认运行时载入了目标数值。脚本偏移和字段容量随版本可能变化，逐样本验证。

复制鉴赏容器也可能带入设置或全局剧情变量，在交付时明确这一影响。目标设备先启动并退出一次游戏以生成存档目录，再复制用户选择迁移的文件。

## 发布清单

交付文件、安装与恢复步骤、原版及译版哈希、内容覆盖范围、验证命令和实际结果共同构成发布记录。区分文件完整性、启动、中文渲染、分支跳转和完整通关各自的证据。

发布可复用 skill 时，逐文件检查通用源码、说明、许可和合成测试。发布目录与私有游戏工程分开，Git 暂存后再次核对路径和内容。
